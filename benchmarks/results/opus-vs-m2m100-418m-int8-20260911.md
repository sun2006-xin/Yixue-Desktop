# OPUS-MT 与 M2M100 418M INT8 首轮对比

日期：2026-09-11
测试集：`yixue-en-zh-baseline-v1`，英译中与中译英各 8 例
运行方式：Windows CPU、本地离线、CTranslate2 4.8.2、INT8、M2M100 beam size 5

## 质量观察

### OPUS-MT 的稳定问题

- 英译中偶尔漏译后半句，例如未翻译 “It is getting warm in here.”。
- 技术术语不稳定，例如把 inference engine 译为“推论引擎”，把 loading 译为“装货”。
- 论文表达易发生近义错译，例如 context 译为“背景情况”。
- 中译英长句整体可读，但部分口语句会遗漏 “next time”。

### M2M100 的稳定问题

- 比 OPUS-MT 更少整句漏译，但语义仍会偏移，例如 “getting warm” 变成“温暖了”。
- 技术句错误更严重：local inference engine 被处理成“當地引擎”，loading 出现“充電”。
- 英译中混入繁体字，和产品当前“中文（简体）”目标不一致。
- 中译英部分论文句比 OPUS-MT 更接近原意，但术语和自然度优势不稳定。
- 资源开销显著增加，不符合预览版“下载即用、轻量、普通电脑可运行”的优先级。

## 决策

1. 预览版继续随包提供双向 OPUS-MT INT8；M2M100 418M 不设为默认、不打入安装包。
2. M2M100 转换产物仅保留为本地实验资产，不接入当前 C++ 工作进程。它需要语言前缀分词协议，不能冒充 Marian/OPUS 模型加载。
3. 当前不从零训练大模型，也不根据 16 个样例直接微调。先建立来源可追踪、许可允许、去隐私的扩展集。
4. 下一轮数据重点覆盖：句子完整性、软件/AI 技术术语、论文语体、简繁一致、数字与符号原样保留。
5. 自有“译学英汉”模型以 OPUS-MT 为首个微调基线；只有在独立盲测中稳定提升且速度/体积不明显恶化时才进入发布包。

## 本轮边界

16 例足以否决 M2M100 作为当前默认包，但不足以宣称 OPUS-MT 已达到正式版质量，也不足以证明任何微调方案有效。后续必须扩展样例并由人工盲评复核。
