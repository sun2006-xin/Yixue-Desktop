# 译学模型与词典发现规格

状态：v0.2（2026-09-13）

## 1. 为什么“发现”不等于“可用”

模型文件格式与推理内核必须匹配。译学把流程拆成：

```text
发现文件 → 识别格式与能力 → 安全校验 → 最小试跑 → 用户分配角色
```

- 发现阶段只读取路径、文件名和受限大小的 JSON 配置，不读取大权重、不执行代码。
- 译学 CTranslate2 包可进入 Rust 完整性与许可证校验，通过后才能启用。
- 千问/Transformers、GGUF、Ollama 清单和 ONNX 可先进入总览；缺少对应内置运行内核时明确显示“已发现 · 需接入运行内核”。
- 未知 ONNX 不猜测用途；只有能从名称或配套元数据确认翻译、语音识别或语音合成时才展示。

## 2. 一键搜索

普通用户无需知道模型文件夹。搜索顺序固定为：

1. `OLLAMA_MODELS` 等已存在的模型目录配置。
2. 用户目录中的默认模型库。
3. 各盘 `models`、`OpenViking\\ollama-models`、`AI`、`LLM` 等常见位置。
4. 本机盘的受限补充扫描。

扫描不访问网络、不跟随链接，跳过系统、回收站、构建产物和依赖目录，并限制深度、条目数与结果数。权限不足的目录直接跳过。后续增加用户可见的停止按钮和扫描范围选择。

## 3. 模型总览

总览显示：模型名称、格式、保存位置、可提供能力、当前状态与可执行操作。四个产品角色保持独立：

- 翻译：专用英汉/多语言翻译模型。
- 理解与总结：千问等通用大模型。
- 语音识别：会议、课程和视频的 ASR 模型。
- 语音合成：单词、句子和口语练习的 TTS 模型。

用户可以用一个兼容多角色的模型覆盖多个角色，也可分别选择。系统提供推荐，普通模式不要求用户理解格式和参数。

对 Qwen/Ollama 候选，当前总览额外提供“接入本地接口”：它只创建一个明确的本地 Provider 配置，不会把普通 Transformers 权重误当成可直接运行的翻译模型，也不会自动安装外部运行时。原生 Ollama 地址使用 `/api`，已有 OpenAI 兼容服务才使用 `/v1`。

模型候选用途与 Provider 实际用途分开保存：候选用途保存在 `model_catalog`，已接入配置的
用途保存在 `provider_profiles`（当前 SQLite schema v9，Provider 角色字段在 v8 引入）。这样重新扫描、路径失效或更新模型目录时，
不会清掉用户已经选择的 Provider 角色。页面会明确区分“候选”“已分配”和“当前使用”；只有
已启用、角色匹配且通过运行时/语言方向校验的 Provider 才能进入正式翻译路由。

## 4. 词典不是模型

词典负责词义、词性、音标、例句、词形、词频、学习阶段与来源；模型负责翻译、解释、总结和判题。两者使用独立页面、数据库表和导入器，避免更换模型时丢失学习资料。

首版词典包计划采用只读、版本化清单加结构化数据：

- 固定词典 ID、版本、语言方向、来源、许可证和内容哈希。
- 限制文件数量、单文件与总大小、字段长度和压缩比，拒绝路径穿越、链接、脚本与可执行文件。
- 导入前预览条目数、字段覆盖、预计空间和许可证；用户确认后写入所选资料库。
- 支持卸载单个词典而不删除用户收藏、批注和学习记录。

## 5. 商业词典边界

牛津、朗文、柯林斯等商业词典不能因为软件免费就随安装包复制。译学只在以下情形接入：

1. 项目取得可分发的书面授权；或
2. 用户拥有合法数据，且来源格式允许个人导入。

译学不抓取付费网站、不绕过 DRM、不复制订阅内容。首版先评估许可证清晰的开放词典候选，再确定可随安装包发布的清单；商业词典入口保留为后续授权能力。
