# 译学发布、隐私与用户控制规格

状态：2026-11-11。本文最初的跨模块边界经用户确认；公开发布采用单独的干净桌面仓库，原开发仓库继续作为私有历史备份。

## 1. 产品与预览发布

- 面向非计算机专业用户，官方功能安装后即可使用，不要求另装 Ollama、Python 或模型管理器。
- 按模块逐项完成；由产品所有者决定何时暂停，先收口当前模块，再将已完成能力组成预览版。
- 不为尚未实现的页面提前打包无用途模型。正式功能需要的推理内核和默认模型随对应安装包提供。
- 初期使用完整离线安装包；具备稳定服务器后再增加按功能选装模型、增量更新和高速下载。

## 2. 本地资料库

- 首次启动选择“译学资料库”位置；默认优先推荐空间充足的非系统盘。
- 仅当用户主动选择 C 盘时，才允许数据库、模型、缓存和临时文件使用 C 盘，并展示预计占用。
- 数据库、模型、缓存、导出和临时文件使用独立子目录，可分别迁移和清理。
- 更新程序不得覆盖资料库。卸载时提供：仅删程序、删缓存/模型并保留个人数据、删除全部。
- 普通记录可在“隐私与数据中心”查看、搜索、导出和分类删除；隐私会话不落库。
- 录音、录屏和导入材料单独征得同意，不因开启历史记录自动保存。

## 3. 模型体验

- 普通模式只展示“一键搜索并推荐”、官方模型状态和翻译/理解/听/说四项能力是否完整。
- 高级模式允许分别选择模型、导入本地模型和配置 API。

## 4. 公开仓库与许可证范围

- 译学 Windows 桌面源码以 Apache License 2.0 发布；新公开仓库只包含桌面 `main` 的当前源码，不带入手机项目开发分支和阅读器源码。
- 原开发仓库保留为私有历史备份，不改公开性、不删除历史分支。
- Apache-2.0 只适用于译学原创源码。词典数据、翻译模型、运行时、Flutter/Rust 依赖与品牌资源按各自来源和许可证分别标注；不得因为仓库根目录的 LICENSE 而将其重新许可。
- Windows 发布包需随附译学许可证、第三方组件/数据说明和所需许可证文本，并且不得带入用户资料库、密钥、录音或录屏。
- 一键搜索先检查环境变量、默认模型库和各盘常见模型目录，再对本机盘做有深度、条目数和结果数上限的补充扫描；界面持续显示扫描状态，不访问网络、不读取模型权重、不执行模型代码，也不跟随链接。
- 登记模型不等于可用；必须完成格式、来源、能力、最小试跑、超时和本地/远程标识。
- 官方本地模型由译学内置运行时直接加载。Ollama、LM Studio 等仅为已有高级环境的兼容入口。
- 模型总览必须区分“已配置、已发现、可校验启用、等待运行内核、文件不完整”，不得把未支持格式笼统显示为损坏。

## 4. 外观与设置

- “模型与服务”和“设置”保持独立页面。
- 设置包含：外观主题、语言与语气、隐私与数据、更新、使用方法、个人声明、用户准则、模型说明。
- 自定义主题支持所见即所得编辑和安全导入/导出；主题包只允许设计令牌、字体声明和图片，不执行脚本。
- 官方三套主题继续保留，自定义入口必须在外观页显著可见并支持一键恢复。

## 5. 专业翻译与个人习惯

- 全局规则保存长期术语、姓名、品牌和表达偏好。
- 项目规则只影响指定论文、课程、公司材料或会议，并优先于全局规则。
- 用户修改译文时可选择“仅本次”“加入当前项目”“设为全局规则”。
- 规则与来源均可查看、导出、停用和删除。

## 6. 更新

- 默认只检查带签名的轻量版本清单；发现更新后提醒，由用户确认下载，不静默安装。
- 用户可关闭自动检查。检查更新不得携带文档、学习记录、设备文件列表或模型内容。
- 预览版与稳定版使用独立渠道；初期可使用公开发布平台，后续迁移到自有更新服务。

## 7. 署名、源码与商业边界

- 对外署名固定为“花鱼鱼”；真实身份仅用于依法登记和必要的权利证明。
- GitHub 仓库 `sun2006-xin/yixue` 保持 Private；是否公开只能由产品所有者明确授权。
- 未来如公开，准确表述为“源码公开/Source Available”，商业使用需授权，不沿用 MIT。
- 个人学习、教育、非营利研究及个人自行在工作中使用免费。
- 企业部署、批量使用、商业集成、转售、换皮、对外服务和商业训练必须取得书面授权。
- “译学”名称、Logo、标语和视觉系统不因源码可见而自动授权。
- 软件代码、模型、训练数据、字体和第三方组件分别维护来源、许可证、修改说明与哈希。

## 8. 发布门禁

- 不含密钥、用户数据库、模型缓存、私人材料或绝对个人路径。
- 安装包、模型包、版本清单具有哈希；正式更新需数字签名。
- 当前 Cargo 中的 MIT 声明是公开发布阻断项；在法律文本审核并替换前不得公开仓库。
- 公开前完成第三方许可证清单、隐私承诺、用户准则、使用帮助和投诉处理渠道。
- 保留 Git 历史、设计源稿、版本包与发布哈希；商标、软著和专利由产品所有者决定时机。
