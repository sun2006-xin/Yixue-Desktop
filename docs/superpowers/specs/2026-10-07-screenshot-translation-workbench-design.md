# 截屏翻译工作台设计规格

**状态：已确认**

**日期：2026-10-07**

**范围：Windows 桌面版 Flutter 应用中的截屏翻译页面、结果窗口、悬浮球、截图历史与截屏生词衔接。**

本规格把用户反馈和已确认决定转成实现约束。当前阶段只交付设计文档；应用实现须在用户审阅本规格后开始。

## 已确认决定

1. 截屏翻译页面成为完整工作台，集成截图历史、原图与文章内容、悬浮球状态、快捷键和截图留存设置。
2. 原截图默认保存在本机。关闭自动留存后，只影响后续截图；既有图片仍保留，用户可在本页清理既有图片。
3. 删除一条截屏翻译历史时，同步删除与该记录关联的原图。
4. 选择 OCR 原文中的英文词语，可以加入独立的“截屏生词”复习集；词义须来自词典或由用户填写确认，不能把整段译文冒充单词释义。
5. 悬浮球由译学自有蓝绿视觉呈现。左键开始截图；右键提供截图、打开工作台、快捷键设置、关闭悬浮球和退出等操作。
6. 不新增有道截图工具栏里未实现的总结、润色、公式等 AI 功能。

## 目标与不做事项

### 目标

- 用户可以从悬浮球、页面按钮或系统快捷键开始截屏，并在原应用仍可使用的情况下查看翻译结果。
- 用户可在同一页面检索、回看、删除截屏翻译记录，查看对应裁剪原图、OCR 原文和译文。
- 截图设置不再散落在通用设置页；悬浮球、快捷键、原图留存与图片清理都从截屏翻译页面进入。
- 原图只在本机归档；翻译服务接收 OCR 文本用于翻译，不接收截图图像。
- OCR 选词能进入学习复习流程，保留足够上下文并明确词义来源。
- 悬浮球状态以窗口实际显示/失败状态为准，避免页面显示“已启用”但桌面上看不到。

### 本次不做

- 不修改 Reader 或 Reader 的开发计划。
- 不改造通用模型/Provider 配置；工作台只链接到共享模型与服务设置，不复制一套配置。
- 不实现云端截图存储、设备同步、自动 OCR 单词对齐、整篇文章导入或额外 AI 摘要功能。
- 不把系统全屏图像作为历史原图；仅保存用户选中的截图区域。

## 页面结构与行为

### 截屏翻译工作台

页面采用桌面工作台结构：

- **顶部操作区**：页面标题与简短说明、主操作“框选翻译”、快捷键提示、悬浮球和原图留存状态，以及本页“截屏设置”入口。
- **左侧历史栏**：按时间倒序列出截屏翻译记录，可搜索 OCR 原文/译文，可删除一条记录。历史查询必须按 `screenshot_translation` 来源过滤，不得只取混合历史的第一页后在 UI 里筛选。
- **右侧内容区**：显示当前记录的原图预览、OCR 原文、译文及来源时间。支持放大原图；原文和译文可复制。宽屏下原文与译文并排，空间不足时改为上下或可切换视图。
- **设置面板**：在当前页面内打开，不跳往通用设置页。包含悬浮球开关与运行状态、快捷键录入/冲突提示、原图自动留存开关、清理已有原图操作及共享模型设置链接。
- **共享配置边界**：源/目标语言和当前翻译 Provider 若已由快速翻译的共享配置管理，应显示当前值或链接到共享设置；不得在本页维护第二份模型凭据。

状态包括首次空历史、加载中、无搜索结果、翻译进行中、翻译失败可重试、原图缺失/保存失败、快捷键冲突、悬浮球启动失败与悬浮球已关闭。错误必须显示下一步可执行操作。

### 截图选择与结果窗口

- 选区仅截取用户框选的矩形区域，背景遮罩轻量且边界/拖拽点清楚。完成选择后自动开始 OCR 与翻译；不要求用户切换到主窗口才能继续原应用操作。
- 结果窗口以浅色内容面板、柔和蓝绿强调色和清楚分区呈现 OCR 原文与译文；支持修改 OCR 文本后重译、复制译文、重新截取、查看历史及置顶/关闭。
- 错误提示放在内容上方的紧凑状态条，不覆盖主要文字，不使用截图中现有的大红色失败文案作为主视觉。
- OCR 文本可选择。选中单个英文词后提供“加入截屏生词”操作；不能选出合法单词时给出简洁提示。
- 只保留当前产品已支持的操作，不照搬参考图中的公式提取、总结、润色或其他未接通能力。

### 悬浮球与右键菜单

- 悬浮球使用译学羽毛/笔尖品牌图形、蓝绿渐变和轻阴影，不复制参考软件的按钮造型。默认尺寸以桌面常驻控件清晰可点、又不遮挡内容为准。
- 左键触发截屏翻译。右键菜单提供“框选翻译”“打开截屏工作台”“设置快捷键”“关闭悬浮球”“退出译学”。
- 主窗口关闭但悬浮球启用时，主窗口隐藏、悬浮球继续显示；关闭悬浮球是显式状态变更；退出应用会结束悬浮球与后台快捷键。
- 应用启动时按已保存偏好创建悬浮球；状态只能在浮窗创建并确认可见后显示“已显示”。启动/恢复失败要把错误反馈给工作台，并保留重新显示操作。

## 本地数据与隐私

### 原图归档

- 原图是用户选中的区域 PNG 字节，不是全桌面截图。
- 文件放在应用数据目录的 `screenshot_translation/` 子目录，以内部生成的历史记录 ID 派生文件名；写入采用临时文件后原子替换，避免留下半张图。
- 截图翻译服务调用显式携带稳定的历史 ID，使历史行和原图路径可重复关联。普通快速翻译继续使用原 ID 生成逻辑。
- 原图字节只流向本地归档模块和本地预览；OCR 文字可传给用户已配置的翻译 Provider。禁止将图片附加到 Provider 请求或诊断日志。
- 每次框选开始时读取并固定本次自动保存偏好，避免处理中途切换设置产生含糊结果。
- 原图保存失败不应丢失已成功的 OCR/译文历史；该条目显示“原图未保存”。只要原图字节仍在当前运行时的会话内存中，就提供重试保存；应用退出后不承诺恢复未成功归档的图片。
- 翻译失败的当前结果窗口可在关闭前重试；v1 历史以已形成翻译历史记录的截图为准。

### 保留、清理和删除

- `自动保存截图原图` 默认开启。关闭后只是不再保存新图，已有图片继续保留。
- “清理已有截图”删除全部截屏原图文件并保留 OCR/译文历史；执行前显示将删除的图片数量/占用空间和确认按钮。
- 删除单条截屏历史会删除历史记录和关联原图。跨数据库/文件系统删除需处理部分失败：界面说明哪一部分失败并给出重试操作；图片清理需要能扫描并删除无历史行对应的孤儿文件，不得静默宣称全删成功。
- 学习集中的生词独立于截图历史；删除截图历史不会删除已保存的生词上下文副本。若跳转回来源记录，记录已删除时显示来源不可用。
- 迁移旧版偏好时，缺少原图开关字段按默认开启处理；现有快捷键和悬浮球设置保持不变。

## 截屏生词数据契约

- 新增/复用名为“截屏生词”的学习集，不依赖“我的收藏”与本地词典交集，未知词也能进入复习。
- 生词至少保存：原词、学习状态、OCR 全文上下文、文章译文快照、来源历史 ID；词典释义或用户确认释义为可选字段，并区分来源。
- `LearningItemData` 的新增字段必须可选；旧版 JSON 读取时用空值补齐，不丢失原复习数据。学习数据采用向后兼容迁移。
- 复习卡片优先展示已确认释义；无词典释义时展示“尚未填写释义”和上下文，不能把文章级译文当作词义。
- 选词约束为单个英文词，允许词内撇号与连字符。OCR 文章上下文完整保存，供用户复习时判断原词意思。
- 选词来自结果子窗口时，子窗口只负责展示选择与动作；学习数据由主窗口/主运行时写入，经现有窗口消息协议传递，避免多个窗口并发改写学习文件。

## 数据流与边界

```text
框选区域 → 本地 PNG → 本地 OCR → OCR 文本翻译 Provider
                    ↘ 本地原图归档（开关开启时）
翻译结果 → 独立截屏历史版本（historyId） → 稳定 captureId → 本地原图文件
OCR 单词选择 → 主运行时 → “截屏生词”学习集（带上下文快照）
```

- 截屏历史使用现有翻译历史表/仓储，增加来源过滤查询能力；无需把图片二进制放进 SQLite/JSON 历史行。
- 每次成功翻译都有独立 history ID，用于批注、截屏生词来源和历史行删除；原图不使用 history ID 命名，而使用跨重译稳定的 capture ID。旧行缺少 `screenshot_capture_id` 时兼容回退到该行自身 ID。
- 删除前由 Core/FFI 查询所选版本删除后不再被其他截屏历史引用的 capture ID。删单个共享版本时保留图；删最后版本或整组时才删图。图像删除失败时不删除对应历史行。
- LearningItem 的可选字段用于保存生词上下文，不在通用翻译历史中嵌入学习状态。
- 悬浮球、全局快捷键、设置偏好均由主窗口/运行时拥有；结果子窗口不直接打开系统快捷键或写持久化存储。

## 验收场景

1. 首次打开工作台可看懂如何开始；无历史和搜索无结果均有可执行引导。
2. 页面按钮、悬浮球左键和快捷键都可开始框选；结果窗口出现后，主应用仍可继续操作。
3. 用户关闭并重开主窗口时，悬浮球仍按偏好显示；若创建失败，页面如实显示失败并能重试。
4. 右键悬浮球可打开明确菜单；快捷键可设置、保存、重启后恢复，冲突时阻止保存并说明原因。
5. 翻译完成后，历史同时显示原图、OCR 原文和译文；重译产生独立版本且共用原图。删除一个版本会保留其他版本的图，删除最后版本才清理该图。
6. 开关关闭后新记录不再保留原图，已归档原图仍可查看；清理原图后历史文字仍可用。
7. Provider 请求中只出现 OCR 文本，不含图像字节；翻译使用离线 Provider 时无网络依赖。
8. 选中词典内和词典外单词都可加入截屏生词；释义来源明确，复习卡能看到上下文；旧学习 JSON 仍可加载。
9. 结果窗口与工作台在常见桌面比例及窄窗口下无内容裁切，键盘操作有可见焦点。

## 风险和实现前检查点

- 原图与历史记录位于不同存储介质，需明确部分失败清理、残留扫描/重试策略。
- 全局历史查询需要可组合来源过滤，避免分页后错误遗漏。
- 真实 Windows 悬浮窗显示受窗口激活、DPI、任务栏区域和多屏坐标影响，源码/Widget 测试无法替代运行桌面验收。
- 快捷键冲突检查需覆盖应用内重复配置与系统注册失败；不得仅按 UI 本地状态显示成功。
- 学习模型序列化和复习 UI 需要共同修改，但仍只在 Flutter 学习数据层完成，不必改 Rust 核心。
