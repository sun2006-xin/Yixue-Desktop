# 截屏翻译常驻入口与悬浮对照框设计规格

日期：2026-10-06
状态：规格已确认；实施计划待确认
产品：译学（Windows Flutter 客户端）
设计系统：[截屏翻译悬浮工作流设计系统](../../designs/截屏翻译悬浮工作流设计系统.md)

## 1. 目标

为译学建立独立于阅读器工作流程的截屏翻译切片。用户可从常驻圆球或可配置的全局快捷键发起屏幕区域截取。截图完成后，目标应用恢复可操作状态；译学以非模态的悬浮对照框显示截图上下文、OCR 原文与译文。每次成功翻译都进入译学现有本地翻译历史。

成功标准：

- 截屏选择只是短暂交互；结果框不会锁住屏幕输入或要求用户切回译学主窗口。
- 可同时查看截取上下文、可修正的 OCR 原文和译文。
- 用户能移动/收起结果框继续使用其他软件，并能通过圆球再次截屏。
- 圆球与快捷键可在设置中管理；快捷键注册失败时能看到原因并换键。
- 翻译复用译学当前 Provider 路由和本地历史，不新建一条并行翻译栈。
- 屏幕图像不默认写入磁盘；网络服务接收 OCR 后的文本用于翻译，不接收屏幕截图图像。
- 阅读器页面、分页和 OCR 行为保持不变；截屏翻译的排期不等待阅读器功能收口。

## 2. 背景与当前状态

当前隔离开发分支已有页面版基础流程：框选区域、本机 OCR、编辑 OCR 结果、调用现有翻译服务，并通过既有翻译回调写入历史。该流程仍需要用户回到译学主窗口继续查看结果，没有常驻圆球、独立结果窗或全局快捷键。当前历史模型包含原文、译文、语言方向、Provider 和时间，但没有截屏来源标记。

本规格已由用户确认。实现计划需单独审阅；计划和执行方式确认后再开始代码实施。

## 3. 用户与范围

### 目标用户

在浏览器、PDF、IDE、视频字幕和其他 Windows 软件中阅读不可复制的外语内容，希望短暂截取文字后继续操作原应用并做原文/译文对照的人。

### 用户故事

- 作为读者，我可以随时点击译学圆球或按全局快捷键开始区域截屏。
- 作为读者，我可以按 Esc 取消选区。
- 作为读者，选区结束后不用切回译学主窗口，也能看到 OCR 原文与自动生成的译文。
- 作为读者，我可以移动对照框、不遮住当前内容，并继续使用原应用。
- 作为读者，我可以修正识别文本并重新翻译。
- 作为读者，我可以在译学历史中找回截屏翻译的原文和译文。
- 作为读者，我可以关闭圆球、更换快捷键或从圆球重新打开译学。

### MVP 范围

- Windows 常驻圆球：单击截屏、拖动移动、设置开关、圆球菜单中的打开主界面和退出。
- 可配置全局快捷键，支持系统级组合键。
- 区域截屏、Esc 取消、本机 OCR。
- 自动翻译、可编辑原文、重译、复制原文/译文。
- 一个可拖动、可收起、默认置顶的结果框；新截图更新当前结果框，之前成功结果进入历史。
- 译学主界面现有翻译历史显示截屏记录并标记来源。
- 设置持久化圆球和快捷键偏好。
- 关闭主窗口但圆球开启时，主窗口隐藏、后台协调器与圆球继续工作；通过圆球可重开主窗口或退出。

### 非目标

- 重做阅读器、PDF 分页或阅读器 OCR。
- 训练/评测翻译模型，或宣传译学翻译质量超过有道/DeepL。
- 默认不加入公式识别、润色、问答或画面内译文覆盖。AI 学习摘要是 2026-10-09 明确追加的可选能力，行为见下方续迭代补充。
- 登录自启或长期保存原始截图图片。
- 单次截取生成多个独立结果窗。
- 无人值守持续录屏或截取屏幕。

### 2026-10-09 续迭代补充

- 用户可在结果窗固定当前物理像素选区；坐标保存在本机偏好。固定选区的再次采集必须由用户显式点击，应用不在后台轮询或自动截取。
- 同一运行会话内，如果再次采集的边界与上一张完全一致，则提示截图内容是否变化。应用重启后不读取历史原图作隐式比较；没有内存中的上一张截图时显示“尚未比较”。
- 用户显式请求 AI 学习摘要时，沿用已分配的“理解与总结”服务，只发送该历史记录中的 OCR 原文，不发送截图。摘要写入对应截屏翻译历史行并随该行删除；清理截图原图不删除摘要。存储失败时清楚提示仅当前查看有效。

## 4. 产品行为

### 启动与圆球

1. 设置中可启用/关闭圆球。设置写入版本化本地偏好文件。
2. 圆球开启时，运行时显示在当前桌面；拖动后靠近最近显示器边缘并吸附。
3. 左键启动截屏；右键菜单提供“打开译学”“截屏翻译设置”“退出”。
4. 圆球关闭时，快捷键仅在译学主进程运行期间有效；关闭主窗口会退出进程。
5. 用户可从设置中的快捷键录制控件改键。快捷键必须是系统全局作用域；注册冲突时显示错误和修改入口。
6. 圆球开启时，关闭主窗口不退出进程，以保证圆球、快捷键和正在处理的结果会话继续工作。

### 截取、OCR 和翻译

1. 圆球单击或全局快捷键发起选区。
2. 显示覆盖层，提示“拖动框选 · Esc 取消”。Esc 随时退出且不创建历史。
3. 首次拖动松开后保留候选框；用户可拖八个控制点调整边缘/角落，或拖框内移动选区。按 Enter 确认捕获，Esc 或右键取消。
4. 确认后结束选区覆盖层并恢复用户原应用输入，译学在本机对选区图像执行 OCR。无文字时在结果框提供“未识别到文字”和“重新截取”。
5. 有识别结果时显示对照框并自动调用当前翻译服务。该操作沿用快速翻译当前 Provider 选择、语言检测/方向处理及错误映射。
6. 服务失败时保留截图上下文和 OCR 原文，可重试；不会生成成功历史。
7. 用户在结果框修改原文并重新翻译时，每次成功结果保存为独立历史版本；失败尝试不覆盖之前的成功版本。
8. 翻译状态显示当前是本地处理还是向已配置 Provider 发送识别文本，不上传截图图像。

### 结果框与历史

1. 整个应用复用一个结果窗；新截取替换当前结果，不堆叠窗口。
2. 结果窗初始位置尽量避开本次选区。若屏幕可用空间不足，允许用户移动或收起。
3. 默认左右对照显示：OCR 原文可编辑，译文可选择/复制。窄窗口切换到“原文/译文”标签模式。
4. 结果窗的截图缩略图只保留在当前会话内存；关闭结果窗或应用退出时释放。
5. 成功翻译进入既有本地翻译历史，历史来源设为“截屏翻译”；若现有 schema 尚无来源字段，通过向后兼容 migration 增加 origin 字段，既有记录默认 quick_translation。
6. 每次成功翻译有独立 history ID；同一张截图的多个版本通过稳定 capture ID 关联同一份本地原图。旧历史没有 capture ID 时，以旧 history ID 作为原图 ID。
7. 删除一个翻译版本时保留其他版本共享的原图；仅当删除选择覆盖该截图的最后一个历史版本时删除原图。批量删除按 capture ID 分组判断。
8. 结果窗的“查看历史”打开译学已有历史工作区。

## 5. 交互参考与原创边界

用户提供的有道截图展示了屏幕遮罩、矩形选区、八个拖点、底部动作条、语言方向、对照开关、复制/图钉/撤销/关闭，以及多个 AI 操作。设计系统记录了图片的估读尺寸和取样颜色。

提取到的规律：

- 明确压暗未选区域，保留选区内容亮度。
- 用边中点与角点让选区修改意图清晰。
- 把操作放在使用者当前视线附近。
- 把语言方向与原文/译文对照作为主要信息。

公开产品交互参考（仅用于操作规律，不作为视觉稿模板）：

- 有道翻译官方产品页列出“截图翻译/钉至屏幕”；较早的有道桌面版帮助描述结果小窗可拖动或固定、闲时收缩。旧帮助只能作为历史交互参考，当前体验以用户实际使用为准。([有道翻译产品页](https://fanyi.youdao.com/vip.html)、[有道桌面版帮助](https://cidian.youdao.com/5.0/help/deskdict5beta/description/03.html))
- DeepL 官方流程支持快捷键、矩形选区、Esc 取消，识别文本进入翻译输入并自动展示译文。([DeepL 截屏翻译说明](https://support.deepl.com/hc/en-us/articles/4407878482962-Use-the-screen-capturing-feature))
- Google Translate 图片翻译提供原文/译文并排、放大译文和复制操作；Chrome Lens 侧边栏可固定或用 Esc 关闭。([Google 图片翻译说明](https://support.google.com/translate/answer/6142483?hl=en)、[Chrome Lens 说明](https://support.google.com/chrome/answer/15086890?hl=en-Gb))
- Windows PowerToys Text Extractor 把快捷键、选区、Esc 取消和复制结果串成短流程；Snipping Tool 的文本动作提供本机 OCR。([PowerToys Text Extractor](https://learn.microsoft.com/en-us/windows/powertoys/text-extractor)、[Windows Snipping Tool](https://support.microsoft.com/en-us/windows/apps/use-snipping-tool-to-capture-screenshots))
译学的原创方向：

- 独有常驻圆球作为入口；不照搬有道入口图标或红色按钮风格。
- 选区期间只显示简短提示与可操作的调整点；框选后按 Enter 确认，再自动识别/翻译；不复制底部全宽工具条。
- 悬浮结果窗负责持续查看，主界面只负责历史与设置。
- 第一版只保留截屏翻译所需操作，不加公式、总结、润色等其他动作。
- 采用现有译学蓝/青绿/新生绿主题与字体令牌。

## 6. 架构选择

### 方案 A：继续放在主窗口页面内

复用现有页面状态，改动最少；但不能同时保持其他应用前景操作，无法满足非阻塞结果框目标。淘汰。

### 方案 B：全部使用原生 Windows 窗体/托盘

可精确控制系统层叠、DPI 与鼠标穿透；需要为圆球、选区、结果面板分别开发/维护 Win32 UI，Flutter 样式和状态管理难复用，开发成本最高。除非 Flutter 多窗能力遇到明确系统限制，否则不选。

### 方案 C：Flutter 多窗口，主引擎协调业务（推荐）

- 主引擎拥有截屏服务、OCR、现有翻译 Provider、历史写入与设置。
- 圆球和结果框作为轻量 Flutter 子窗口复用 Flutter UI；圆球只发起操作，结果框只展示/编辑当前会话。
- 主引擎接收圆球发来的截屏请求，执行捕获与 OCR，调用现有翻译回调并保存历史，再把会话状态发送到结果窗。
- 历史来源通过 Core SQLite schema、FFI 响应和 Dart 历史类型端到端传递；默认来源为 quick_translation，截屏来源为 screenshot_translation。
- 结果窗编辑原文/触发重译时发送命令给主引擎；不能在子窗中再创建另一套 Provider 或数据库。
- 屏幕捕获操作仍由主引擎中的现有截图服务执行，避免子引擎重复初始化截屏插件。
- 全局快捷键注册在主引擎；应用关闭时按圆球设置决定退出还是保留后台主引擎。
- Windows 子引擎需注册所需 Flutter 插件；跨窗消息带会话 ID，丢弃过期请求，避免快速连续截取时晚到结果覆盖新结果。
- 多显示器与 DPI 坐标以系统屏幕坐标为准；圆球、选区、结果窗边界统一换算。

选择理由：复用当前 Flutter UI 和翻译/历史主链路，同时让阅读器保持原样。多窗插件的 Windows 注册与子引擎管理是主要技术风险，需要在实施计划中设置早期验证项。

## 7. 状态与失败恢复

| 情况 | 用户可见行为 |
|---|---|
| 截屏被 Esc 取消 | 回到原应用，不显示错误，不写历史 |
| 没识别到文字 | 结果框显示空识别状态，提供重新截取 |
| 翻译中 | 立即显示截图上下文和 OCR 文本，明确显示处理中 |
| Provider 未配置/不可用 | 保留 OCR 文本，显示现有 Provider 错误与设置入口 |
| 快捷键已占用/注册失败 | 设置里显示冲突；不伪装注册成功 |
| 子窗通信中断 | 不丢主引擎历史写入；用户可重新打开结果窗恢复最近会话 |
| 主窗关闭且圆球开启 | 主窗隐藏，圆球和后台协调器仍可用 |
| 主窗关闭且圆球关闭 | 正常退出应用和热键 |

## 8. 数据与隐私

- 截图以 PNG 字节在当前内存会话内传递；不因启用历史而保存原始图片。
- OCR 临时文件按现有 OCR 实现使用，并在识别后清理。
- 成功翻译持久化原文、译文、语言方向、Provider、时间与翻译来源 origin；新增来源字段默认值为 quick_translation，旧记录保持可读；截屏记录写 screenshot_translation。
- 远程 Provider 请求只包含 OCR 文本和现有翻译上下文；图像不会远程上传。
- 日志不记录图片字节、完整原文或 API 凭据。
- 用户可通过既有隐私数据管理清理翻译历史。

## 9. 验收条件

- 启用圆球后，主窗口关闭仍能从圆球发起截屏；圆球菜单可重开主窗口或退出。
- 关闭圆球后，圆球不出现；主窗口关闭会退出应用。
- 圆球单击和已注册全局快捷键都能打开选区；选区可移动/缩放，Enter 确认，Esc 取消不留下结果或历史。
- 选区跨显示器/不同缩放比例时可见范围与最终 OCR 图像一致。
- 确认或取消选区后焦点/输入返回原应用，结果框不要求切回译学。
- 结果框可拖动、收起、恢复、置顶/取消置顶；新截图更新当前窗。
- 原文和译文对照清晰，OCR 原文可修改，重译后产生正确的一条历史记录。
- 成功翻译记录在译学既有历史中可恢复并标记截屏来源；取消和失败不伪造成功记录。
- 原图按用户已确认的本地保存偏好保存在本机；删除最后一个共享该图的历史版本后，该图不再留在归档目录。
- 模型状态、服务错误、快捷键冲突均可理解且可恢复。

实现阶段用户可以另行要求真实窗口交互验证；在没有执行此类验证前，源码或 Windows build 不能代替多屏/DPI/置顶行为验收。

## 10. 实施切片建议（需规格获批后另写计划）

1. 多窗口最小探针：独立圆球窗发消息到主引擎；主引擎创建/更新结果窗；验证 Windows 插件注册。
2. 圆球与快捷键偏好：圆球窗口、点击启动、拖动吸边、快捷键设置、关闭/退出生命周期。
3. 对照结果窗：截图预览、原文/译文双栏、自动翻译、编辑重译、复制、收起/置顶。
4. 历史收口：Core SQLite 来源字段迁移、FFI/Dart 历史模型传递来源、主页面展示截屏标识、失败/取消边界。
5. 桌面验收：Windows debug build、单屏和多 DPI 屏幕操作、前后台与退出生命周期。

## 11. 实现提示

- 先读当前截屏页面和现有历史写入路径，再以稳定接口连接新窗口。
- 不改阅读器页面或分页算法；OCR 调用要保持在截图功能适配层，阅读器开发节奏不作为截屏工作阻塞。
- 当前截图页面可保留为译学主界面入口/历史入口，但核心交互迁移到非模态结果窗。
- 小球和结果框必须遵循 [截屏翻译悬浮工作流设计系统](../../designs/截屏翻译悬浮工作流设计系统.md)。
