# 译学助手：产品与技术框架

版本：v0.3
目标平台：Windows 桌面端
首批语言：英汉双向
数据原则：本地优先，默认不上传

## 1. 模型、推理引擎和软件的关系

```text
用户界面
  ↓
翻译服务接口（统一协议）
  ├── 本地 CTranslate2 适配器
  ├── 本地 ONNX/其他运行时适配器
  ├── 用户自定义本地模型适配器
  └── 用户自定义 API 适配器
        ↓
模型文件或远程 API
```

- 模型：真正负责生成译文的参数文件，例如 M2M100 418M。
- 推理引擎：负责加载模型、分词、CPU/GPU 计算、量化和生成结果，例如 CTranslate2。
- 翻译软件：负责截图、输入、文章、历史、词典、学习记录、设置和结果展示。

模型不是软件，推理引擎也不是模型。软件通过统一适配器调用不同模型，这样以后更换本地模型或 API 不需要重写页面。

多语言、总结与语音不绑定成一个巨型模型。正式能力分层、千问角色、Ollama/API 兼容门禁和 ASR/TTS 边界见
[`模型能力与兼容架构.md`](模型能力与兼容架构.md)。

## 2. 用户自定义模型与 API

### 模型来源类型

1. 内置本地模型：安装或首次下载时提供，是默认英汉翻译路径，核心能力永久免费。
2. 用户导入本地模型：选择模型目录，软件读取模型格式、语言方向、版本和许可证声明。
3. 用户配置远程 API：作为可选增强，手动填写 API 地址、模型名、请求格式和密钥。
4. OpenAI-compatible API：作为通用兼容入口，但必须由用户主动开启。

### 本地模型分层

- 轻量默认档：英译中采用 `Helsinki-NLP/opus-mt-en-zh`，中译英采用
  `Helsinki-NLP/opus-mt-zh-en`，分别建立低内存、低延迟基线。
- 质量对照档：以 `facebook/m2m100_418M` 的 CTranslate2 INT8 包验证长句、文章和术语一致性。
- 译学微调档：不从随机参数重新训练；分别从上述两个方向模型继续训练，只使用有明确授权、
  去隐私、人工复核的数据生成“译学英汉”版本，并保留原模型署名及修改说明。
- API 增强档：默认关闭，不作为免费核心功能的依赖，也不得在本地模型失败时静默上传内容。

### 安全规则

- API 密钥使用 Windows Credential Manager 或系统安全存储，不写入普通配置文件和日志。
- 默认提供“仅本地模式”；启用远程 API 时显示明确的上传提示。
- 远程 API 配置单独显示“会发送什么内容”，截图、文章和视频不得静默上传。
- 记录供应商、模型名、版本、时间和错误码，不记录完整原文和密钥。
- 自定义模型导入前检查文件路径、格式、大小、哈希、许可证和恶意文件风险。

## 3. 翻译正确性、语义和优美度的来源

翻译质量不是只由模型大小决定，主要由以下因素共同决定：

1. 模型本身：训练数据、语言方向、领域覆盖和模型架构。
2. 上下文：单句翻译容易歧义；文章翻译需要前后文、人物和术语一致性。
3. 分段策略：过短会丢上下文，过长会超出上下文限制或变慢。
4. 术语表：人名、专业词、缩写、产品名需要用户可控的固定译法。
5. 预处理：OCR 错字、断行、标点、数字和代码混入都会降低结果质量。
6. 后处理：数字、单位、链接、代码、专有名词和格式需要规则保护。
7. 提示或解码参数：温度、beam size、长度限制和语言标记会影响稳定性。
8. 质量评估：必须使用固定样本和人工复核，不能只相信模型自评。

## 4. 是否需要针对性训练

第一版会为自有微调预留数据和评测接口，但不在没有基线证据时盲目训练。先完成：

- 正确的英汉基础模型。
- 句子/段落分段。
- 用户术语表。
- 文本预处理和格式保护。
- 翻译记忆和本地缓存。
- 用户纠正后的回收样本。

只有当固定评测证明存在稳定错误，并积累了足够的、经过人工确认且具有授权的数据，才开始小规模微调或蒸馏。个人用户的私密文章、截图、字幕和学习记录默认永不进入训练集；用户纠正也只保存在本机，除非用户主动导出训练包。

建议的质量提升顺序：

```text
基础模型
  → 领域/术语配置
  → 上下文分段
  → 格式与专名保护
  → 用户纠正反馈
  → 评测集回归
  → 只有必要时再微调
```

## 5. 软件技术方案

### 推荐组合

- 跨平台界面：Flutter，统一支持 Windows、Android 和 iOS。
- 核心内核：Rust，通过 Dart FFI 被 Flutter 调用。
- 翻译推理：CTranslate2；Windows 默认 CPU INT8，并在兼容 GPU 上提供加速，移动端使用更小的量化模型。
- OCR/ASR：独立原生适配器，不把某一个供应商写死在学习逻辑中。
- 数据库：SQLite，默认存储在本地数据目录。
- 配置：版本化 JSON/TOML；密钥使用系统安全存储，不进入配置文件。
- 安装：Windows `.msi` 或 Setup `.exe`，Android/iOS 使用各自发行包，模型包与主程序分离。

Tauri 2 作为 Windows 轻量壳备选；如果未来证明移动端和 WebView 交互足够稳定，再评估是否使用 Tauri 替代部分客户端壳。

生产版不让 Python 常驻后台。Python 只可用于模型转换、评测和开发工具，避免把解释器、依赖和启动时间带进最终客户端程序。

## 6. 跨平台核心目录

```text
core/
├── core-domain/       词、句子、文章、题目、进度
├── translation-core/  分段、术语、模型路由
├── learning-core/     每日计划、复习、判题、错题
├── content-core/      文章、词典、PDF、词表解析
├── media-core/        OCR、ASR、截图、字幕
├── storage-core/      SQLite、缓存、迁移、导入导出
├── provider-core/     本地模型与用户 API
└── sync-core/         后续可选同步
ui/
└── flutter_app/       Windows、Android、iOS 共用界面
```

电脑和手机共享 Rust Core，但可以根据硬件选择不同模型；翻译接口、学习记录和页面行为保持一致。

macOS 与 iOS 也沿用同一方案：共享 Flutter UI、Rust Core、数据库结构和 Provider 接口，但分别生成 macOS 与 iOS 安装包。窗口、菜单栏、文件权限、截图、触控、后台限制、Keychain、通知和音频等通过平台适配层实现。iOS 的最终构建和发布需要 macOS/Xcode。

## 6. 页面结构

采用大型软件的固定结构，但不做“AI 聊天窗口化”：

```text
左侧主导航
├── 首页
├── 快速翻译
├── 截屏翻译
├── 阅读器
├── 学习
├── AI 同传
├── 模型与服务
└── 设置
```

五大核心功能固定为：

1. 快速翻译。
2. 截屏翻译。
3. 阅读器。
4. 学习。
5. AI 同传。

首页负责聚合入口；模型与服务、设置属于支撑页面，不计入五大核心功能。
“AI 同传”覆盖英文视频、网页课程、直播课和会议交流，不再使用
“实时字幕工作台”作为用户可见名称。

每个功能单独页面，页面内部保持统一：

- 左侧：模块导航和任务入口。
- 中间：当前核心内容。
- 右侧：解释、历史、术语和操作面板，可折叠。
- 顶部：全局搜索、任务状态、快捷键提示和隐私状态。

设计原则：

- 不使用大面积渐变、悬浮聊天气泡和无意义 AI 装饰。
- 默认只展示当前任务需要的信息，复杂设置放入高级面板。
- 关键操作支持键盘快捷键和拖放。
- 长文章、词典和视频页面使用虚拟列表，避免内容多时卡顿。
- 翻译状态明确显示“本地处理”或“已发送到某 API”。

### 6.1 已确认视觉基线

主界面以用户确认的界面图为正式方向：

- 固定深海军蓝侧栏，当前页面使用明亮蓝色选中块。
- 主工作区使用白色和极浅灰背景，不使用大面积渐变。
- 快速翻译采用原文/译文双栏，右侧为可折叠学习信息卡；输入或选中英文单词即可联动词典解释。
- 底部固定显示本地/远程处理状态、当前模型和快捷入口。
- 直角与小圆角并用，边框和阴影克制，保持大型桌面软件的稳定感。
- 动效只表达页面切换、任务状态和直接操作反馈，不做无意义漂浮。

## 7. 学习页面

“学习”合并原来的单词本，不按身份切成四条固定路径，而是让所有用户按目标、水平、内容和时间自由组合训练。

### 学习目标

- 词汇：小学基础、初高中、大学、考研和专业词汇逐级学习。
- 阅读：英文文章、期刊、用户导入材料，支持边读边点词翻译。
- 考试：教材/考试词表、每日背诵、默写、填空、做题和句子翻译。
- 口语：音标、读音、跟读、复述、情景问答和沟通表达。
- 听力：听写、跟读、对话和视频片段。
- 写作：拼写、造句、中英互译、短文改写和职场表达。
- 专业英语：学科、职业和自定义术语表。

用户可以组合“考研词汇 + 期刊阅读”或“职场口语 + 邮件写作”等目标。

### 内容资源

- 分级词汇、词典、音标、发音、搭配和例句。
- 按难度、主题、专业和长度组织的英文文章与期刊材料。
- 用户导入 TXT、Markdown、HTML、PDF、CSV/TSV 词表和自定义句子。
- 从翻译、阅读和视频中采集单词、句子和段落。

版权内容必须区分用户拥有、已授权和公开许可资源；不能未经授权捆绑整本付费词典或期刊。

### 训练模式

- 每日背词、英汉互译、默写、句子组合、句子判断、填空和错题复习。
- 用户输入 `apple` 等答案后，先做拼写/词形/规则判断，再由模型解释语义、语法和自然度。
- 合理但不唯一的表达显示“可以，但有更自然表达”，不简单判错。
- 每道题保存答案、判定依据、建议和复习结果。
- 一个词可以同时进入背词、发音、听写、造句、阅读和口语任务；一个句子可以拆成词汇、语法、听力和翻译练习。
- 阅读器支持点击词、短语、句子和段落，分别展示解释、翻译、语法、跟读和学习入口。
- 每日计划由用户设置词数、口语时间、阅读量和强度，系统再根据错误和复习规律安排，不强迫固定打卡。

## 8. 自定义主题

单独的“外观主题”页面支持导入/导出主题包，主题包只包含版本号、颜色变量、字体声明和图片资源，不允许脚本执行。

可自定义：页面背景、主色、强调色、侧栏、卡片、边框、阴影、字体大小、界面密度、圆角和动效强度；支持安全导入、导出和一键恢复官方主题。

内置主题固定为三套：生机、浅色、深色。生机承载蓝绿品牌外壳；浅色和深色减少装饰，
服务于论文、长时间阅读和低光环境。动效等级（完整/减少/关闭）与主题独立；阅读器等页面
仍可临时覆盖全局主题。用户自定义主题作为独立入口，不扩大官方主题组合数量。

导入时校验 JSON、图片类型、文件大小、资源数量和路径，防止主题包影响数据和运行安全。

## 9. 交互与性能

- 页面切换使用轻量位移、淡入和状态过渡，按钮、收藏、判题和翻译完成必须即时反馈。
- 支持 hover、focus、active、disabled、loading、empty、error 等真实状态。
- 使用 `transform`/`opacity` 优先，支持减少动效模式，避免大面积模糊和持续重绘。
- 不整页刷新，保留输入、滚动位置和筛选条件。
- 翻译、导入、判题和模型加载放入后台任务，长内容使用虚拟列表。
- 输入判题和搜索使用防抖；普通点击反馈目标小于 100 ms，页面切换目标小于 300 ms（不含模型计算）。
- 记录启动时间、内存、页面切换、滚动帧率和翻译队列等待时间。

## 10. 阅读器与论文版式

阅读器支持 PDF、DOCX、TXT、Markdown，后续增加 EPUB。论文阅读采用两个
独立但联动的视图：

1. 原版视图：直接渲染原始页面，版式、公式、图片、表格、脚注、引用和页码
   不发生改变。
2. 译文视图：按原页面的文本块、栏、标题层级和图表锚点生成中文对照页面，
   与原版滚动、选区和批注联动。

双栏论文、公式和图表不能先粗暴转成连续纯文本。解析顺序为：

```text
原始页面
  → 页面坐标与文本块
  → 栏/标题/脚注/图表/公式结构识别
  → 段落级上下文翻译
  → 原版与译文块位置关联
  → 批注、标签、总结与导出
```

- PDF 导出以版式保真和稳定阅读为目标，可选择原译对页或译文重建版。
- Word 导出以可编辑为目标，保留标题、段落、图片、表格、批注和引用关系；
  不把 Word 的流式排版伪称为像素级 PDF 复刻。
- AI 概要中的每条内容保留来源页码和段落锚点，可跳转回原文。
- 扫描论文需要 OCR，并明确标示识别置信度和待复核区域。

## 11. AI 同传

AI 同传统一服务于视频学习、网页视频、直播课和会议：

- 分别捕获系统声音和麦克风，并保留说话人来源。
- 实时显示原文与中文译文，可使用可拖动、缩放、置顶的字幕窗。
- 用户可选择仅保存字幕，或明确开启录屏/录音。
- 记录带时间戳的原文、译文、说话人和修订结果。
- 结束后生成知识点、课程概要、会议纪要、待办事项和术语表。
- 点击字幕、纪要或知识点可跳转到本地录制的对应时间。
- 不绕过会员、DRM、网站权限或会议安全限制。
- 录制必须主动开启并持续显示状态，默认仅保存字幕，避免静默录制和磁盘失控。

## 12. 悬浮截屏翻译

- 快速框选模式：快捷键进入选区，松开后立即恢复电脑操作。
- 持续取景框模式：保留可拖动、缩放的小方框，只在画面发生变化时重新 OCR。
- 翻译卡可置顶、折叠、调透明度和忽略鼠标点击。
- 原文与译文可对照、复制、朗读、收藏并加入学习。
- 截屏图片是否保存由用户选择；文字历史默认本地保存并可统一总结。

## 13. 第一版开发顺序

1. 建立 Flutter + Rust Core 空壳和 D 盘数据目录。
2. 定义 Core 领域对象、SQLite schema、FFI 边界和统一翻译接口。
3. 做“快速翻译”页面和 Windows 本地运行基线。
4. 接入 M2M100 418M 的 CTranslate2 本地适配器。
5. 加入模型管理页：本地模型目录、启用/停用、版本、许可证和性能信息。
6. 加入 API 管理页，但默认关闭远程调用。
7. 完成悬浮截屏翻译和本地历史。
8. 完成论文阅读器、原译对照、批注、总结及 PDF/Word 导出。
9. 加入学习页面：每日背词、默写、句子组合和句子判断。
10. 完成 AI 同传字幕、可选录制、时间轴和总结。
11. 用同一个 Rust Core 编译 Android/iOS 最小移动端壳。
12. 加入主题包安全校验并完成性能、隐私和离线回归。
