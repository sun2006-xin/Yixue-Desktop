# 译学本地推理运行时规格

当前状态：英译中与中译英均已完成 Flutter 页面到随包模型的离线闭环；Windows 进程内释放模型存在
上游线程退出死锁，已改为独立常驻工作进程隔离。界面方向切换和按请求编号取消均已接通。

## 目标

普通用户安装译学后即可离线翻译，不要求安装 Python、Ollama、LM Studio 或其他开发工具。
模型是数据，运行时是软件内核的一部分；二者分别校验、分别更新。

## 首版技术基线

- CTranslate2：4.8.2，CPU 首版，后续按硬件能力增加 GPU 后端。
- 翻译模型：双向 OPUS-MT INT8，英译中与中译英分别打包和记录许可证。
- 分词：SentencePiece C++，每个模型包固定携带 `source.spm` 与 `target.spm`。
- 软件接口：Rust `CTranslate2Provider` 只接收 `VerifiedModelPackage`，不得直接加载未校验目录。
- 隐私：本地推理失败时直接返回本地错误，不得自动改走网络 API。

## 数据流

```text
原文
  -> source.spm 分词
  -> CTranslate2 Translator（CPU / INT8）
  -> target.spm 还原
  -> 非空与取消检查
  -> 翻译结果
  -> 本地历史与活动记录
```

## 运行时边界

Rust Core 定义安全的 `CTranslate2Runtime` 接口，负责统一取消、语言方向、空输出和错误分类。
平台层通过随软件打包的独立工作进程调用 C++ 运行时，不把第三方推理库加载进 Flutter/Rust 主进程。
工作进程和运行时 DLL 只能从应用安装目录加载；模型目录中的 DLL、EXE、脚本和未登记文件一律拒绝。

首版每个已加载模型对应一个常驻工作进程，请求串行执行并复用模型。取消、超时、协议损坏或进程崩溃时，
主程序终止该工作进程并丢弃当前结果；不得写入成功历史，也不得自动切换到网络 API。

## 工作进程协议 v1

- 通道：标准输入/输出上的 UTF-8 JSON Lines；标准错误仅用于无原文的诊断信息。
- 每条消息必须包含 `schema_version: 1`、请求 `id` 和 `command`。
- `open`：携带已经由 Rust 校验通过的绝对模型目录；成功后返回 `ready: true`。
- `translate`：携带待翻译文本；成功后返回 `translation`。
- 响应必须回传相同 `id`，并使用 `ok`、稳定错误 `code` 和面向用户的简短 `message`。
- 单条协议消息上限 1 MiB，首版单次翻译文本上限 50,000 个 UTF-8 字节。
- 首版不依赖优雅关闭：主程序给予短暂退出窗口后强制结束工作进程，确保第三方线程无法卡住主程序。

## 模型包新增硬要求

除 `config.json`、`model.bin`、源词表和目标词表外，首版模型包必须包含：

- `source.spm`
- `target.spm`

两者与其他模型文件一样写入 `yixue-model.json` 并校验 SHA-256。

## 验收条件

- Windows Release 包在无 Python、无 Ollama 环境下完成英中和中英翻译。
- 真实模型通过工作进程协议返回翻译，随后工作进程可在 2 秒内被终止，主程序不等待第三方析构。
- 畸形、超大和顺序错误的请求被稳定拒绝；协议标准输出不得混入日志，标准错误不得包含用户原文。
- 首次加载、热启动、短句和长句延迟有真实数据，不用估算值。
- 固定 16 条英汉基准生成逐条结果，人工评审准确性、自然度、术语和格式。
- 取消请求不会写入成功历史；本地失败不会发起网络请求。
- 安装包列出 CTranslate2、SentencePiece、模型来源及许可证。
